# LVGL 9.5.0 → 9.6.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every environment from LVGL 9.5.0 to 9.6.0 (latest, released 2026-09-16, the final v9 release) with no user-visible behaviour change and a build free of LVGL deprecation warnings.

**Architecture:** LVGL comes from the PlatformIO registry, pinned per env in `platformio.ini` and configured by the single partial `src/lv_conf.h`. The bump is a version change, `lv_conf.h` updates that pin 9.5's behaviour where 9.6 changed a default, and a mechanical move off the flag API that 9.6 deprecates. Every LVGL call site lives in `src/main_lvgl.cpp`.

**Tech Stack:** PlatformIO, Arduino-ESP32 (S3 and P4), LVGL 9.6.0 (`lvgl/lvgl@9.6.0`, registry).

**Spec:** None separate. This plan argues from LVGL's own `docs/src/changelog/migration-v9-6.mdx` and `CHANGELOG.mdx` at tag `v9.6.0`, and from a trial build (below).

## Findings that shape the plan

- **Trial build (2026-10-12):** `tdeck-pro` against 9.6.0 with only the version changed built with **0 errors**. Flash used was 3,855,233 B and RAM 171,812 B. All 1,436 warnings were deprecations:
  - 548 `#warning LV_COLOR_DEPTH is deprecated … Define LV_COLOR_FORMAT_DEFAULT instead`
  - 888 `lv_obj_add_flag` / `lv_obj_remove_flag` / `lv_obj_has_flag` deprecated in favour of `lv_obj_set_<flag>()` / `lv_obj_is_<flag>()`.
- **Unchanged in 9.6 (verified in the 9.6.0 source):**
  - `library.json`, apart from the version number;
  - the v8/v9.x API maps, so `lv_obj_clear_flag` still compiles;
  - `LV_MEM_POOL_INCLUDE` / `LV_MEM_POOL_ALLOC`, which put the pool in PSRAM;
  - `src/misc/cache/instance/lv_image_cache.h`, included at `src/main_lvgl.cpp:79` for `lv_image_cache_drop`;
  - `LV_FONT_CUSTOM_DECLARE`, the `lv_font_fmt_txt` font format, and `#include <lvgl.h>`.
- **Defaults 9.6 changed that we depend on:**
  - `LV_USE_ASSERT`, `LV_USE_ASSERT_NULL` and `LV_USE_ASSERT_MALLOC` now default to 0. In 9.5, NULL and MALLOC were 1.
  - `LV_OBJ_STYLE_CACHE` now defaults to 1 (was 0). That costs more per-object pool memory, which matters on `cardputer-cap`, the only env without PSRAM (80 KB pool).
  - `LV_USE_CHECK_ARG` is new and defaults to 1, with logging off. It only adds cheap NULL checks, so keep the default.
- **We use no other deprecated API.** None of these appear in `src`: `lv_list`, `lv_menu`, `lv_win`, `lv_subject_*`, `lv_qrcode`, `lv_snapshot`, `lv_draw_sw_*` calls, `lv_display_*(NULL…)`, or `LV_COLOR_FORMAT_NATIVE`.
- **Flag call sites:** there are 536, all in `src/main_lvgl.cpp`. 531 pass one `LV_OBJ_FLAG_*` constant, which LVGL's `scripts/migration/migrate_obj_flags.py` converts (it handles `lv_obj_clear_flag` too). Five need hand conversion: lines 13501, 32833, 43037, 56147 and 56174 (multi-line or nested-call arguments). All nine flags we use have setters in 9.6: `scrollable`, `clickable`, `hidden`, `ignore_layout`, `floating`, `overflow_visible`, `send_draw_task_events`, `scroll_elastic`, `gesture_bubble`.

## Global Constraints

- Pin exactly `lvgl/lvgl@9.6.0` in every env. There are 11 `lib_deps` lines; `p4-amoled-lr2021` and `crowpanel-50` inherit theirs.
- No user-visible behaviour change: where 9.6 changed a default, `lv_conf.h` pins the 9.5 value explicitly, with a comment saying so.
- Change only `platformio.ini`, `src/lv_conf.h` and `src/main_lvgl.cpp`. Do not touch `.pio/libdeps`.
- Build only the envs a step names (project rule: minimal builds). CI's `build.yml` builds all envs on push.
- Flash a board only in Task 3, where hardware evidence is the point.
- Work goes into the composite PR (CLAUDE.md, "The composite PR"), and the PR description is rewritten in full, keeping its existing `Fixes #110` line.

## Review Focus

1. **T-Deck Pro (I1 e-ink) after the blend-path rewrite.** 9.6 rewrote the software blenders, including `I1` solid fills and `I1` decode. Text and the separator lines must look the same as on 9.5, with no stray grey or dither pixels. Checked on device in Task 3.
2. **Cardputer pool headroom.** No PSRAM and an 80 KB pool. Opening the emoji picker over a full DM view must not log `couldn't allocate` or a tiny_ttf "cache not allocated" error. The `[lvgl] openLiveModal pool used=N%` reading must stay within 3 points of 9.5. Checked in Task 3.
3. **Textarea handlers after "only send one event when updating text".** The handlers are `onAccentFieldChanged` (:12624), `onSpellFieldChanged` (:12875) and `onComposeInputChanged` (:13777, :14045). Typing, accent replacement, spell correction and the compose character counter must each update once per keystroke, with no lost updates and no feedback loops. Checked in Task 3.
4. **Emoji (tiny_ttf) glyphs.** 9.6 fixed a kerning-cache use-after-free and changed how missing glyphs are handled. Emoji must render, and an unknown emoji must show the fallback box, not a blank or a crash. Checked in Task 3.
5. **State maps / map tiles through lodepng.** 9.6 now rejects 16-bit-per-channel PNGs. The 8-bit OSM tiles and state maps must still render on the Locate/Map screens, with no `Error decoding PNG` on serial. Checked in Task 3.

### Task 1: Bump to 9.6.0 and pin 9.5 behaviour in `lv_conf.h`

**Files:**
- Modify: `platformio.ini` (the 11 `lvgl/lvgl@9.5.0` lines)
- Modify: `src/lv_conf.h:7` (colour format) and the assert / style-cache settings

**Interfaces:**
- Consumes: nothing.
- Produces: every env builds against 9.6.0, with `LV_COLOR_FORMAT_DEFAULT == LV_COLOR_FORMAT_RGB565`, `LV_OBJ_STYLE_CACHE == 0`, `LV_USE_ASSERT == 1`, `LV_USE_ASSERT_NULL == 1` and `LV_USE_ASSERT_MALLOC == 1`.

- [ ] **Step 1: Record the 9.5 baseline.** On the composite branch before any change, run `pio run -e tdeck-pro -e tdeck -e cardputer-cap`. Copy each env's `RAM:` and `Flash:` lines into the PR's Testing section.
- [ ] **Step 2: Change the version.** `sed -i '' 's|lvgl/lvgl@9.5.0|lvgl/lvgl@9.6.0|' platformio.ini`. Then `grep -c 'lvgl/lvgl@9.6.0' platformio.ini` must print `11`, and `grep -c '9.5.0' platformio.ini` must print `0`.
- [ ] **Step 3: Edit `src/lv_conf.h`.**
  - Replace `#define LV_COLOR_DEPTH 16` with `#define LV_COLOR_FORMAT_DEFAULT LV_COLOR_FORMAT_RGB565`, and rewrite the comment beneath it to say 9.6 derives `LV_COLOR_DEPTH` from this.
  - Next to `LV_USE_ASSERT_MEM_INTEGRITY 0`, add `LV_USE_ASSERT 1`, `LV_USE_ASSERT_NULL 1` and `LV_USE_ASSERT_MALLOC 1`, with a comment that these are 9.5's defaults, which 9.6 turned off.
  - Add `#define LV_OBJ_STYLE_CACHE 0`, with a comment that 9.6 turned it on by default and that it stays off until its pool cost is measured on `cardputer-cap`.
- [ ] **Step 4: Build.** Run `pio run -e tdeck-pro -e tdeck -e cardputer-cap 2>&1 | tee /tmp/lv96.log` (or the scratchpad).
  - Expected: all three `SUCCESS`.
  - `grep -c 'LV_COLOR_DEPTH is deprecated' <log>` prints `0`.
  - `grep -c ' error: ' <log>` prints `0`.
  - The only remaining LVGL warnings are the flag deprecations.
  - Add the new RAM/Flash lines next to the baseline.
- [ ] **Step 5: Commit.** `git add platformio.ini src/lv_conf.h && git commit -m "LVGL 9.6.0: bump all envs; pin 9.5 assert and style-cache defaults"` (with the session's attribution lines).

### Task 2: Move off the deprecated flag API

**Files:**
- Modify: `src/main_lvgl.cpp` (536 call sites)

**Interfaces:**
- Consumes: Task 1's 9.6.0 libdeps. The script is `.pio/libdeps/tdeck-pro/lvgl/scripts/migration/migrate_obj_flags.py`.
- Produces: no `lv_obj_add_flag`, `lv_obj_clear_flag`, `lv_obj_remove_flag` or `lv_obj_has_flag(_any)` left in `src/`. Each becomes `lv_obj_set_<flag>(obj, true|false)` or `lv_obj_is_<flag>(obj)`.

- [ ] **Step 1: Run LVGL's migration script on the one file.** The script takes a file or a directory, rewrites matching calls in place, and imports only stdlib modules (read it once to confirm; it is downloaded code). First run `python3 -I .pio/libdeps/tdeck-pro/lvgl/scripts/migration/migrate_obj_flags.py --test`, which must end with `All N tests passed`. Then run `python3 -I .pio/libdeps/tdeck-pro/lvgl/scripts/migration/migrate_obj_flags.py src/main_lvgl.cpp`.
- [ ] **Step 2: Convert the five sites the script skips by hand.**
  - Lines 13501 and 43037: an OR of flags cast to `lv_obj_flag_t`. Use one `lv_obj_set_<flag>(obj, false)` per flag in the OR.
  - Line 32833: `lv_obj_set_clickable(lv_obj_get_child(card, (int32_t)i), false)`.
  - Lines 56147 and 56174: multi-line `lv_obj_add_flag`. Use the matching setter with `true`.
  - (Line numbers are from before Step 1 and may have moved; find the sites with the Step 3 grep.)
- [ ] **Step 3: Check that nothing is left.** `grep -nE 'lv_obj_(add|clear|remove|has)_flag' src/` prints nothing.
- [ ] **Step 4: Review the diff mechanically.**
  - `git diff --stat` touches only `src/main_lvgl.cpp`.
  - `git diff | grep '^-' | grep -c '_flag('` is about 536.
  - `git diff | grep '^+' | grep -cE 'lv_obj_(set|is)_'` should be at least that.
  - Read every `lv_obj_has_flag` → `lv_obj_is_` hunk: the script joins OR'd `has_flag` tests with `&&` and `has_flag_any` tests with `||`. Check that each condition kept its meaning, and that `!lv_obj_has_flag(...)` became `!lv_obj_is_...(...)`.
- [ ] **Step 5: Build.** `pio run -e tdeck-pro -e tdeck -e cardputer-cap`. Expected: all `SUCCESS`, and `grep -c 'is deprecated' <log>` prints `0`.
- [ ] **Step 6: Commit.** `git commit -am "LVGL 9.6: dedicated per-flag setters/getters in place of lv_obj_*_flag"`.

## Out of scope (follow-ups)

- Turning on `LV_OBJ_STYLE_CACHE`. It is a measured change: compare the Cardputer pool reading and the screen-switch time with it on.
- Moving the `lv_image_cache.h` include to `lvgl_private.h`. It compiles warning-free today, but `src/` headers are private in 9.6 and go away in v10.
- LVGL v10 preparation beyond the flag API (none other found today).
